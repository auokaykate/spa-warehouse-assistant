# Складской ИИ-помощник спа-оператора (MVP)

Модуль интеллектуальной обработки складских данных из трёх функций:

| Часть | Функция | Что делает | LLM |
|---|---|---|---|
| 1 | `normalize_movement(text) -> dict` | разбирает текстовую запись движения товара в `date, sku, location, operation, qty, unit, batch, doc_no` | нет |
| 2 | `forecast_demand(history, sku, horizon_days, params) -> dict` | прогноз потребности, страховой запас, точка заказа, рекомендуемая закупка с округлением до упаковки и минимальной партии, стоимость, дата дефицита, confidence и объяснение | **нет, расчёт детерминированный** |
| 3 | `answer_question(question, context) -> (dict, float, str)` | интент и сущности вопроса, уверенность, ответ с объяснением. Числа берутся только из Части 2 | Claude (опционально) + fallback на правилах |

Результаты прогона на тестовых данных и обоснование решений: [RESULTS.md](RESULTS.md).

## Установка

Нужен Python 3.11 или новее (проверено на Python 3.14.0, Windows 10).

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

В Windows (PowerShell) venv активируется командой `.venv\Scripts\Activate.ps1`.

`anthropic` нужен только для LLM-режима. Без ключа, без сети и даже без установленного пакета всё работает на правилах.

## Запуск тестов

```bash
python -m pytest -v
```

## Запуск пайплайна

Одна команда прогоняет все три части: M1–M8, три позиции на горизонтах 30 и 90 дней и 15 вопросов.

```bash
python main.py
```

Отчёт печатается в консоль и сохраняется в `output/report.md` (Markdown-таблицы), полные результаты сохраняются в `output/results.json`.

Флаги:

- `--no-llm`: принудительно только правила, даже если задан ключ;
- `--quiet`: не печатать отчёт, только сохранить файлы;
- `--output DIR`: каталог для отчёта.

### LLM-режим (необязательно)

```bash
export ANTHROPIC_API_KEY=...
python main.py
```

LLM (модель `claude-opus-5-5`, structured outputs по JSON-схеме) включается, если установлен пакет `anthropic` и задан `ANTHROPIC_API_KEY`. Отключить его можно через `SPA_USE_LLM=0` или `--no-llm`. При любой ошибке API, отказе модели или невалидном ответе запрос тихо уходит на правила.

## Архитектура

```
dataset.json, catalog.json     данные из Приложений 1 и 2
main.py                        CLI: прогон пайплайна, отчёт
spa_assistant/
  config.py      все пороги, коэффициенты, словари, регулярные выражения
  data.py        загрузка JSON
  normalize.py   Часть 1: разбор записи движения
  forecast.py    Часть 2: прогноз и рекомендация закупки (без LLM)
  llm.py         необязательный слой Claude: разбор вопроса и перефраз ответа с проверкой чисел
  qa.py          Часть 3: интенты, сущности, unknown, ответы
  report.py      Markdown-таблицы для отчёта
tests/           pytest: даты и единицы, округление, прогноз, вопросы
output/          результаты последнего запуска (report.md, results.json, pytest.txt)
```

Поток данных:

1. **Часть 1.** Запись разбирается последовательно: партия → дата → объект → SKU → документ → операция → количество. Каждый найденный фрагмент маскируется, поэтому цифры из `MS-02`, `CONS-052` или даты не попадают в количество. Количество приводится к базовой единице позиции из справочника.
2. **Часть 2.** Пропуски в ряду интерполируются, затем ищется устойчивый сдвиг уровня спроса и одиночные выбросы (фильтр Хампеля). Прогноз строится сглаживанием Холта с затухающим трендом. Дальше считаются страховой запас, точка заказа и нетто-потребность, объём округляется вверх до упаковки и не ниже минимальной партии, стоимость берётся по цене справочника. Confidence равна произведению факторов: длина истории, волатильность, полнота, горизонт, режим спроса.
3. **Часть 3.** Интент оценивает LLM или словарь ключевых слов с весами. Если разрыв между первым и вторым интентом меньше 0.25, название подходит нескольким позициям («масло» → OIL-001 или OIL-002), не хватает обязательных параметров или вопрос вне домена, возвращается `unknown` с уточняющим вопросом. Ответ собирается шаблоном из результата `forecast_demand`. Если спрошен филиал, а данные есть только по сети, ответ начинается с фразы «По филиалу «…» данных нет». Если LLM переформулирует текст, в каждом его числе проверяется совпадение с черновиком, иначе используется шаблон. У каждого ответа два независимых флага: `needs_clarification` («требуется уточнение вопроса») и `low_forecast_confidence` («низкая уверенность прогноза»).

Все числовые параметры находятся в `spa_assistant/config.py`: коэффициенты Холта, пороги сдвига уровня и выбросов, веса confidence, порог «требуется уточнение», порог разрыва интентов, веса ключевых слов.
